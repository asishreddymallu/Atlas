# Verification

Independent checks of the simulator. Each checker gets its expected values
from a model written separately from the product: the RISC-V unprivileged
spec, IEEE 754, the textbook 5-stage pipeline, or a textbook cache. It then
compares those values with what the simulator's own code does. Nothing
expected is ever read back from the simulator.

This is separate from the GoogleTest suite (`test/`). Several suite tables
were generated by these scripts, and the [tables check](#7-committed-tables)
proves they still are.

## Running it

```bash
scripts/run_verification.sh            # build the probes, run everything (~17 min)
scripts/run_verification.sh --no-build # reuse build-verify
```

The script does the following:

1. Configures `build-verify` with `-DATLAS_BUILD_VERIFICATION=ON`. That switch is OFF by default, so the normal build has no extra targets.
2. Builds the three probes.
3. Runs every checker below.
4. Writes each checker's summary line to `verification/out/summary.txt` and compares it with `verification/expected_summary.txt`.

It prints `VERIFICATION PASSED` and exits 0 only when every checker ran, every summary matches, and every negative control was caught. Full logs are in `verification/out/<step>.log`.

Requirements:
- Python 3 (standard library only);
- the project's own build requirements (CMake, Ninja, Qt 6);
- `sha256sum`.

Output:
- Everything generated goes to `verification/out/`, which is git-ignored and recreated on each run. Set `ATLAS_VERIFY_OUT` to put it elsewhere, and `ATLAS_BUILD_VERIFY` to use another build tree.
- Nothing generated is committed. Every corpus is rebuilt by the scripts from fixed seeds (`random.Random(20261119)`, and `random.seed(1)` in the FP self-test), so two runs produce identical files.

`--record` copies the new summary over `expected_summary.txt`. Use it only after an intended change, with the diff reviewed. The same applies to `asm/dump_all.sh --record`.

## How the simulator is driven

There are three small C++ probes in `probes/`. They link `atlas_core`, the same library the GUI and the CLI use, and run each program on a fresh processor of each of the five models through `StepAndNotify()`:

| Probe | Used by | What it does |
| --- | --- | --- |
| `atlas_verify_sweep` | ISA sweep, hazard sweep, li audit | `list`/`names` print the assembler's own mnemonic tables. `words` prints each program's machine words. `run <model> <batch> <out>` runs every program of a batch file and prints the final pc, steps, cycles, x0-x31, f0-f31, fcsr and 32 scratch dwords. |
| `atlas_verify_cacheprobe` | cache sweep | Runs one program with a given L1 geometry and policy, and prints hits, misses and evictions for L1, the instruction cache and L2. It counts evictions two ways: the cache's counter, and tag changes seen between steps. |
| `atlas_verify_asm` | assembler corpus | `code` prints the machine words, data and symbols; `tokens` the lexer's tokens; `errors` the parser's errors. |

Every probe runs through `lib/run_hermetic.sh`, which gives it a throwaway XDG home (seeded with a fixed theme and font size) and its own `vm_state/` directory. The probes refuse to start without that (`lib/hermetic_guard.h`), so a run can never edit `~/.config/Atlas/Atlas.conf` or the checkout's `vm_state/`.

## The checkers

Runtimes are from one full run on the development machine (Fedora 44, 24 threads); the probes' 5 models run in parallel.

### 1. FP oracle self-test (`lib/selftest.py`, ~1 s)

**Proves:** the IEEE 754 / RISC-V F+D oracle (`lib/fpo.py`), which works on bit patterns with exact `Fraction` arithmetic, agrees with the host's correctly rounded double arithmetic. It checks 20,000 random add/mul/div pairs and 5,000 square roots in round-to-nearest-even.

**Expected:** `bad 0`.

### 2. ISA sweep (`isa/sweep.py`, ~95 s)

**Proves:**
- Every mnemonic the assembler accepts runs to the same final state on all five models. The list comes from the assembler's own tables (`lists`), not a hand-written one.
- That state equals an independent RV64IM oracle and the F/D oracles.

**Method:** every instruction gets operands from a `.data` table and is padded with four nops, so every model is inside its contract.

**Steps:** `lists`, then `gen` (writes `batch.s` and `manifest.json`), `run` (5 models), and `compare`.

**Expected:**
- `170 mnemonics, 140 swept, 15328 programs`.
- `0 model divergences, 0 oracle mismatches, 5 distinct assemble errors`. The five errors are expected rejections, identical on every model: `fmv.s.x` and `fmv.x.s` are names with no encoder entry, and `slliw`, `sraiw` and `srliw` are given shift amount 32, which is out of range for a W shift (0-31).

### 3. Hazard and cycle sweep (`hazard/hazgen.py`, ~12.5 min)

**Proves:** this is the cycle oracle. Each unpadded producer → k fillers → consumer program (63,056 of them):
- gives the same final state on h-nf and h-f as on rvss;
- takes exactly the number of cycles an analytic 5-stage recurrence predicts. The recurrence covers ID-time stalls, branch and jump redirects, and CSR serialisation.
- leaves the rvss result equal to the oracle.

It also reports:
- the nh-f contract cases;
- the minimal filler count nh-nf needs per producer class.

**Steps:** `gen`, `run`, `compare`. The report is written to `out/hazard/report.md`.

**Expected:**
- `programs 63056, assemble/run errors 0`;
- 0 state divergences, 0 cycle mismatches and 0 oracle mismatches;
- 1 known nh-f contract case (`feq.s -> jalr.rs1`, k=3);
- `nh-nf fails at k=3: [] (0)`.

### 4. `li` audit (`tables/li_audit.py`, ~80 s)

**Proves:** for 6,161 values, every `li` expansion the assembler emits computes its value:
- **decoded and emulated** in Python from the spec;
- **run** on rvss, h-f, h-nf and nh-f.

The values are the whole 0x7FFFF800..0x7FFFFFFF range, the ±2^11/2^31/2^32/2^63 boundaries and 2,000 seeded random values.

**Steps:** `values`, `encode now`, `run now`.

**Expected:** `0 wrong` everywhere.

### 5. L1 cache sweep (`cache/run_all.py`, ~40 s)

**Proves:** for 315 runs (9 cache-lab programs × 7 L1 configurations × 5 models), the simulator's hit, miss and eviction counts equal a textbook set-associative cache (`cache/cachemodel.py`). That model is fed the address trace of a tiny independent RV32 interpreter (`cache/miniiss.py`).
- **L1:** compared on every model.
- **Instruction cache and L2:** compared on rvss only.
- **End state:** each program's final x8 must also match.

The 7 configurations are:
- direct-mapped 256 B and 1 KB;
- 2-way and 4-way LRU;
- 2-way FIFO;
- 4-way 512 B write-back/write-allocate;
- 2-way 128 B FIFO.

**Expected:** `rows 315 mismatches 12`. All 12 are the same known difference, recorded and unchanged since the sweep was written: L2 on rvss for `matmul_ijk` and `matmul_jik` under the six write-through/no-write-allocate configurations. The simulator forwards a missed store to L2 one byte at a time, so it counts as four L2 misses where the textbook model counts one (783 vs 207 = 192 stores x 3; known_issues 130). Every L1 row and every other L2 and instruction-cache row matches. `run_all.py` exits 1 while any mismatch remains; `run_verification.sh` judges it by the summary, which pins the 12. Raw counts go to `out/cache/probe.json` and `results.csv`.

### 6. Assembler corpus (`asm/dump_all.sh`, ~6 s)

**Proves:** the assembler's machine code, tokens and parse errors for 58 programs are byte-identical to the recorded result. The 58 are:
- the 44 example programs listed in `asm/corpus.txt`;
- 8 directive programs and 6 broken programs in `asm/inputs/`.

That is 174 dumps, compared against `asm/expected.sha256`. Any assembler change that alters a program in the corpus shows up. The broken programs check that errors keep their lines, columns and messages.

**Expected:** `programs: 58, dumps: 174` and `asm: differing 0, missing 0, unexpected 0`.

### 7. Committed tables (`tables/check_tables.py`, ~1 s)

**Proves:** the 18 expectation tables committed under `test/` are exactly what their generators print today. The generators are:
- `tables/`, `timing/`, `hazard/gen_tables.py` and `gen_subset.py`;
- `cache/gen_cases.py`.

Each computes expected values from the spec or a model, never from the simulator. So the suite's expectations are reproducible, and none was edited by hand.

**Method:** each blank-line-separated block of the generator's output must appear in the target file. Comment lines and indentation are ignored.

**Expected:** `tables 18, matching 18`.

### 8. Negative controls (`negative_controls.py`, ~50 s)

**Proves:** every checker above can fail. Each control plants exactly one wrong value in a copy of a fresh result. It then reruns that checker's own comparison on the copy, and requires exactly one more problem than on the untouched result. The controls:

| Control | What is planted |
| --- | --- |
| ISA | one register flipped in rvss's output |
| Hazard | one h-f cycle count +1 |
| Cache | one L1 hit +1 |
| Assembler | one machine word changed in one dump |
| Tables | one expected hit changed in a copy of `test/cache_lab_cases.inc` |

**Expected:** five `CAUGHT` lines and `controls 5, caught 5`.

## Layout

| Path | Contents |
| --- | --- |
| `lib/` | Shared code, not specific to one checker:<br>- `common.py`: RV64IM ALU, encoders, padded-program builder;<br>- `fpo.py`: IEEE/RISC-V F+D with flags;<br>- `p6_oracle.py`: exact binary32 rounding;<br>- `selftest.py`;<br>- `vpaths.py`: paths;<br>- `probeio.py`: probe output parser;<br>- `run_hermetic.sh`, `hermetic_guard.h`. |
| `probes/` | The three probes and `probes.cmake`, which the root `CMakeLists.txt` includes under `ATLAS_BUILD_VERIFICATION`. |
| `isa/`, `hazard/`, `cache/`, `asm/` | The sweeps. |
| `timing/` | `gen_timing.py` (the pipeline timing cases) and `gen_hdu.py` (the hazard unit's false stalls). |
| `tables/` | The generators of the committed test tables, `li_audit.py`, `gen_pcrel.py`, `part0_expect.py`, and `check_tables.py`. `data/li_words_before.txt` is a pinned record of the `li` expansion lengths the assembler emitted before the known_issues 110 fix: `gen_li.py` keeps every expansion that long. It cannot be regenerated, because the old assembler is gone. |
| `negative_controls.py` | Section 8. |
| `expected_summary.txt` | The summary lines a passing run prints. |
| `RESULTS.md` | The last full run: counts, commit, date. |

The scripts were developed out of tree, in a private `~/atlas-verify` folder, and copied here without their generated corpora, binaries, logs or the screenshot and UI harnesses. Comments in several test files still name the old location. They map as follows:

| Old path in a test comment | Now |
| --- | --- |
| `~/atlas-verify/e3/gen_{call,dround,li,shift,w}.py`, `li_audit.py` | `tables/` (same names) |
| `~/atlas-verify/e4/gen_{csr,csr_pseudo,fclass,fcvt_int,fdiv}.py` | `tables/` (same names) |
| `~/atlas-verify/e5/gen_fflags.py`, `gen_dflags.py` | `tables/gen_fflags.py`, `tables/gen_dflags.py` |

| `~/atlas-verify/e8/` (`gen_cases.py`, cache model) | `cache/` |
| `~/atlas-verify/pcrel/gen.py` | `tables/gen_pcrel.py` |
| `~/atlas-verify/harness/*probe` (UI harnesses) | not imported |
